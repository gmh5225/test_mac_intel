# AMD SVM guest execution

The workflow runs the same x64 guest images on hosts that advertise AMD SVM through KVM. Each image already executed in QEMU TCG. The manifest binds the images, IR and machine objects to their SHA-256 digests. Two original guests check the RCX result after VMEXIT and the address-size override. Four generated guests additionally check 50 register, xstate and continuation cases apiece. Each guest reports its result through the debug console and an exit port.

The original guest is reproducible with `verify_vmrun_context.py --baseline --keep original`. The two C inputs come from `neverd_x64_continuation_source_v1` applied to the same x64 instructions with the `amd-svm-v10` profile. Pass each source to the fixture verifier with `--neverd-continuation` and the x64 NeverC frontend. The generated guest images use the X86 backend from the pinned LLVM release at O0 and O2. The small Multiboot loader sets up the x64 guest before entering the test. [NeverC guest verifier](https://github.com/NeverSight/NeverC/blob/f3eb95aa50cd6e7d99082d783d2a515ff71cf87c/tests/neverc/X86/verify_vmrun_context.py) · [NeverD source](https://github.com/NeverSight/NeverD/tree/0a5979c1e6e2f95207e3808f15f0ea9d8b8033ab) · [LLVM r7](https://github.com/NeverSight/llvm-project/releases/tag/neverd-llvm-v23.0.0-r7)

The host loads the fixture's program segments into a single KVM vCPU and starts its Multiboot entry point in 32-bit protected mode. Four hardware breakpoints identify the original VMRUN and VMEXIT continuation, the route-specific address-size override, and the instruction four bytes later. The host checks the four opcode bytes in the loaded image before running the guest. A return requires consecutive observations at the selected instruction and its successor with the same full RAX. A tagged fault requires the processor to save that instruction address and its original RAX. The receipt records the register image and the guest's VMCB exit code at each observed point. The generated functions execute without replacement or relocation.

Each optimization level also has a mapped-address guest from the same verifier. That input supplies a physical address within guest RAM for both operand widths. The tagged-address guest supplies the same low bits and a nonzero upper half for `67 0f 01 d8`. The host compares any resulting architectural `#GP(0)` frame to the independently executed original. The report counts completed guest contexts and observed exceptions separately. [AMD VMRUN addressing](https://docs.amd.com/api/khub/documents/j44LvPXzuuXgM0WyHKQfeQ/content) · [Linux nested SVM](https://github.com/torvalds/linux/blob/v6.18/arch/x86/kvm/svm/nested.c)

For each generated image, the checker locates the unique `67 0f 01 d8` in the native `__llvm_x86_vmrun_context.1` helper. Its single direct caller must be the original NeverD step `neverd_step_v10_1010`. Tagged images retain their matched full ELF files. Mapped images carry their symbols in the Multiboot file itself. The checker verifies each file's digest and explicitly selects x86-64 disassembly for both ELF containers. Original images use the fixture's `original_vmrun_addr32_rax` instruction.
